1. What The Agent Does
One-paragraph overview + the 5 outputs it produces per run

The SchedulerAI agent is a conversational AI assistant that turns a single plain-English sentence into a fully scheduled meeting. A user types something like "Schedule a sync with Alice tomorrow at 3pm for 30 min" in the chat; the agent extracts the structured meeting details, asks clarifying questions for anything missing, checks calendar availability, resolves conflicts, lets the user pick a video platform, and creates the event automatically — no manual calendar work required.

What It Produces, Per Run

#OutputDetail
1Structured meeting objectTitle, participants, emails, date, time, duration — extracted from free text
2Calendar eventCreated on the user's connected calendar (Google or Outlook)
3Video meeting linkGoogle Meet, Zoom, or Microsoft Teams join URL, generated automatically
4Auto-sent invitesAll participants emailed via the calendar provider's native invite system
5AI summaryOne-paragraph confirmation shown in the chat after scheduling

2. Functionality
The conversational Q&A flow, confirmation, and selection steps

2.1 Conversational Validator — Missing-Field Q&A

Before scheduling, the agent asks targeted follow-up questions for any field it couldn't extract from the user's free text. This logic lives in MeetingService.findMissingFields() and is asked one field at a time, in this fixed order:

OrderFieldQuestion Asked
1meeting_title"What is the meeting about?"
2participants"Who should be invited? List their names separated by commas, or type 'just me' to skip."
3email_<name> (per participant)"What is the email address for <name>?" — only asked if the email can't be resolved from contacts or calendar history
4date"Please provide the meeting date."
5time"Please provide the meeting time."
6duration"Please provide the meeting duration (e.g. 30 min, 1 hour)."
💡
A user can answer multiple fields in one reply — e.g. "tomorrow 3pm for 30 min" fills date, time, and duration at once.

2.2 Confirmation & Inline Editing

Once all required fields are filled, the agent shows a summary (title, date, time, attendees, duration, task, owner) and asks the user to reply "confirm" or describe a change. Inline edits are supported in natural language — e.g. "change time to 5pm", "make it 2 hours", "add John as attendee" — parsed and applied without restarting the flow.

2.3 Platform & Slot Selection

StepBehaviour
Platform selectionIf the user named a platform explicitly ("use Zoom"), it's auto-selected. If exactly one platform is connected, it's auto-selected. Otherwise the agent shows buttons for each connected platform.
Slot selection (date + time given)A smart conflict check runs against the connected calendar(s). If free, the requested slot is shown for direct confirm. If busy, the nearest 3-5 free alternatives are offered.
Slot selection (date only)All free slots for that day are listed for the user to pick from.

2.4 End-to-End Flow

User types: "Schedule a sync with Alice tomorrow at 3pm for 30 min" | v Extract -> AI parses text into a structured meeting object | +-- missing fields? --> conversational Q&A (Section 2.1) --+ | | v | Confirmation summary <--------------------------------------------+ | v Platform selection (if >1 connected) -> Slot selection / conflict check | v Email resolution for any unconfirmed participant | v Schedule -> event created + invites sent + join link generated | v Confirmation card: title, time, attendees, join link, calendar link

3. Agent Architecture
State machine, shared schema, and the components that power it

3.1 Orchestration — Phase State Machine

The agent is a client-side state machine (useChatFlow.js) that routes each user message to a handler based on the current phase, then transitions to the next phase. Every step is a discrete REST call to the backend — no streaming.

PhaseMeaning
IDLEAwaiting a new scheduling request, or just finished one
PICKINGUser is choosing which of several extracted meetings to proceed with
MISSINGAsking the field-by-field Q&A from Section 2.1
EMAIL_CONFIRMResolving/confirming a participant's email address
CONFIRMShowing the summary, accepting "confirm" or an inline edit
PLATFORMUser picking a meeting platform from connected options
SLOTSUser picking a time slot from available options
DONEMeeting scheduled; ready for the next request
CANCEL_CONFIRMConfirming a meeting cancellation
RESCHEDULE_TIME / RESCHEDULE_CONFIRMCollecting and confirming a new time for an existing meeting
FOLLOW_UP_SELECTUser picking which past meeting to schedule a follow-up to
NEEDS_NEW_TIMERequested time was in the past; asking for a future time

3.2 Shared Meeting Schema

Every phase reads and writes the same meeting object, defined by the agent's extraction prompt:

{
  "id": "unique-id-1",
  "meeting_title": "string | null",      // concise title, never invented
  "participants": ["Full Name 1", ...],
  "participant_emails": { "Full Name 1": "email | null" },
  "task": "string",                       // what needs to be done
  "owner": "string | null",               // person responsible
  "deadline": "YYYY-MM-DD | null",
  "date": "YYYY-MM-DD | null",
  "time": "HH:MM (24h) | null",           // start time only, never a duration phrase
  "duration": "number (minutes) | null"   // never defaulted — always asked if missing
}

3.3 Components Behind The Agent

ComponentRoleAI Calls
PromptBuilderBuilds the extraction prompt and the summary prompt sent to the active AI provider; resolves relative dates ("tomorrow") before they reach the model2 per meeting (1 extraction, 1 summary)
MeetingServiceOrchestrator — coordinates extraction, missing-field detection, availability checks, platform creation, invite sending, and summary generation—
ConflictServicePure logic — computes free/busy slots and checks a requested slot for conflicts; merges Google + Outlook busy times when both are connectedNone
CalendarService / OutlookCalendarServiceGoogle Calendar & Microsoft Graph API wrappers — create/update/delete events, search attendees, fetch recent meetingsNone
Meeting platform providersGoogle Meet, Zoom, Teams (implemented), Webex (stub) — create the video join link for the selected platformNone
IntegrationServiceReports which calendar/meeting providers a user has connected, used to populate the PLATFORM-phase selection buttonsNone
✅
The agent is provider-agnostic — it runs on any of Groq (default), OpenAI, Claude, or Gemini, selected by a single environment variable, with no code changes required to switch.
